interest-rate-models

Four parallel implementations (Python reference, C++, Rust, Java) of the core fixed-income modelling stack: discount-curve construction from deposit/FRA/swap/OIS quotes, the Vasicek short-rate model, a curve-fitted Hull-White one-factor model with caplet/swaption calibration, and the Bachelier normal model for bp-vol quoting. All four ports share one golden-value suite of 33 cases with absolute tolerances, every numerical kernel (Brent, bisection, Nelder-Mead, erfc normal CDF, exact OU moments) is implemented natively, and API_SPEC.md pins the semantics every port must honour.

What the latest review found and fixed. The integrated Ornstein-Uhlenbeck variance used in the exact-transition Monte Carlo cancels three O(dt) terms; the plain formula was 80× wrong at a·dt = 1e-7 and a max(·, 0) guard hid it. The fix uses expm1 plus a six-term power series below a·dt ≈ 1e-2 (< 3e-15 relative below the threshold, < ~1e-11 above). The same review made the Vasicek calibration honest — three starts, at_bound, parameter spreads and an identified flag, because the bundled yields have two minima within 2 % rmse — added the |g(r*)| < 1e-10 Jamshidian contract, maturity bounds that stop a days-typed maturity from being UB in C++ / a panic in Rust / a 16 GB allocation in Java, and Hull-White calibration + Bachelier vols. Goldens were regenerated (33 cases, 7 new) and all four ports re-pinned. Still a limitation: MC streams are not bit-identical across languages; agreement is statistical only.

What's inside

Discount curve & bootstrap

DiscountCurve with log-linear interpolation in ln(DF) (piecewise-constant instantaneous forwards), flat-forward extrapolation, continuous zeros, instantaneous/simple forwards and a par-swap-rate helper; DF > 1 is legal so negative rates are first-class. The sequential single-curve bootstrap solves each pillar from deposits, FRAs and annual par swaps (plus an OIS variant) with a native Brent root find, rejects crossed quotes by name and never relabels other solver failures.

Vasicek short-rate model

dr = kappa(theta − r)dt + sigma dW: affine A/B closed-form ZCB prices and yields, exact mean/variance of r_T, the Jamshidian (1989) ZCB call/put formula, and exact-transition (bias-free) Monte Carlo of (r, ∫r dt) with a reported standard error. Calibration to zero yields uses native Nelder-Mead from three starts with sigma_fixed, at_bound, spread and identified diagnostics — non-convergence is reported, never thrown.

Hull-White one-factor

Fitted to a market curve: theta(t) from finite-difference forwards, affine ZCB via market DFs (exact reproduction at t = 0), ZBC/ZBP closed forms, caplets/floorlets as ZCB options, caps as caplet strips, Jamshidian swaption decomposition with the enforced |g(r*)| < 1e-10 contract exposed through jamshidian_at_r_star, tree-free exact-Gaussian MC, and calibrate_hullwhite fitting (a, sigma) to caplet/payer-swaption prices with an a_fixed option.

Bachelier normal model

Price and implied normal (bp) volatility for caplets and swaptions, so model prices can be compared with broker quotes; the demo reports the calibrated Hull-White model's caplet and swaption bp vols. Round-trips to 1e-12 in the data generator and is pinned in the golden suite.

Native numerical kernels

No external numerics in any port: Brent (zbrent) and bisection root finders that reject non-finite values and never return an unconverged root, a Nelder-Mead simplex with penalty-based domain handling, normal CDF/PDF via erfc (Cody's CALERF in Rust and Java), and exact OU step moments using expm1 plus a power series so they stay correct down to a·dt ~ 1e-12.

Golden suite & validation

data/golden/golden.json holds 33 cases with flat scalar inputs and absolute tolerances; every language runs one test per case (parameterised in C++/Java/pytest, collect-all in Rust) so a single bad case never masks another. generate_data.py validates before writing: quotes reprice to < 1e-9, closed forms agree with 200k-path MC within 3 SE, calibrations recover their generating parameters to 1e-9.

Validation & error contract

NaN/inf in any input, non-positive DFs, unsorted or duplicate pillars, empty inputs, out-of-range maturities, wrong-length starts and non-representable results (exp overflow, DF underflow) all raise the language's standard error; every loop is bounded. converged is true only if tolerances were met and the solution is not on a domain boundary; price on a calibration only when converged and (identified or sigma/a fixed).

Units, conventions, scope

Times are ACT/365F year fractions on a continuous axis; zeros are continuously compounded, deposits/FRAs/forwards simple, fixed legs annual with a short first stub; volatilities are absolute (sigma = 0.01 is 100 bp/√year). Deliberately out of scope: other day counts, calendars, IMM dates, futures convexity, multi-curve basis, smile/skew, time-dependent parameters, Bermudan exercise and analytic Greeks (DV01 is a bump-and-reprice recipe in the COOKBOOK).

References

(1998); Cody (1969) for erfc; Bianchetti & Carlicchi (2011) and Schrimpf & Sushko (2019) for the multi-curve/RFR context.

Quick start

git clone https://github.com/AshJha0/interest-rate-models && cd interest-rate-models

# Python reference (3.11; numpy; pytest + scipy only as test cross-checks)
cd python
PYTHONPATH=src python3 demo.py           # run the demo
PYTHONPATH=src python3 -m pytest -q      # 220 passed
cd ..

# C++ (g++ 13, C++17, CMake >= 3.16, GoogleTest)
cd cpp
bash build.sh                            # cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2
./build/demo
ctest --test-dir build --output-on-failure   # 130 passed
cd ..

# Rust (1.95, edition 2021)
cd rust
cargo build --release                    # zero warnings
cargo run --release --bin demo
cargo test --release                     # 102 passed
cd ..

# Java (21, JUnit 4 + Hamcrest — no Maven/Gradle)
cd java
bash build.sh                            # javac -Xlint:all -Werror everything into out/
bash demo.sh
bash test.sh                             # JUnitCore on all *Test classes (162 passed)
